1  Introduction to R Programming

1.1 A toy example

Throughout this unit we will use one running example to introduce the basic building blocks of R: vectors, strings, special values, matrices, data frames, lists, functions, file I/O, and graphics.

The mission: a class of 100 students has taken four quizzes, each scored out of 100 points. Each student’s final grade is the average of their best three quiz scores – that is, we drop each student’s single lowest quiz score before averaging. To make things realistic, quite a few students missed one quiz or another, so we also need to handle missing values correctly. We want to

  1. work out the calculation step by step for one student,
  2. package that calculation into a reusable function,
  3. apply the function to every student to get a full set of results, and
  4. present those results as a table and as plots.

This mirrors how real data-analysis code is usually built: explore on one case, generalize into a function, then apply and report.

1.2 Step by Step, for One Student

1.2.1 Vectors: recording quiz scores

The score on each quiz, across all students, is naturally stored as a vector. We simulate a class of 100 students, each quiz scored out of 100, using rnorm and clipping the result to a valid 0-100 range with pmin/pmax:

Code 
set.seed(123)
n <- 100

gen.quiz <- function(mean, sd)
{
    x <- round(rnorm(n, mean, sd))
    pmin(100, pmax(0, x))
}

quiz1 <- gen.quiz(78, 12)
quiz2 <- gen.quiz(74, 14)
quiz3 <- gen.quiz(80, 10)
quiz4 <- gen.quiz(70, 15)

To make the data realistic, we then mark a random 10% of the entries in each quiz as missing – a student who did not sit that quiz:

Code 
miss.rate <- 0.10

quiz1[sample(n, round(n*miss.rate))] <- NA
quiz2[sample(n, round(n*miss.rate))] <- NA
quiz3[sample(n, round(n*miss.rate))] <- NA
quiz4[sample(n, round(n*miss.rate))] <- NA

head(quiz3, 20)
 [1] NA 93 77 85 76 NA 72 74 NA 79 81 82 92 NA 70 97 76 73 NA 67

Ordinary arithmetic propagates a missing value rather than silently ignoring it, which is exactly the safe default we want:

Code 
mean(quiz3)
[1] NA
Code 
mean(quiz3, na.rm = TRUE)
[1] 80.83333

1.2.2 Strings: naming the quizzes and students

We could type out "Quiz1", "Quiz2", … by hand, but paste0 builds such labels programmatically – a habit that pays off the moment there are 40 quizzes instead of 4:

Code 
quiz.names <- paste0("Quiz", 1:4)

quiz.names
[1] "Quiz1" "Quiz2" "Quiz3" "Quiz4"

With 100 students, typing out individual names is not realistic either. sprintf generates zero-padded IDs like "S001", "S002", … in one line – exactly the kind of job it is built for:

Code 
students <- sprintf("S%03d", 1:n)

head(students)
[1] "S001" "S002" "S003" "S004" "S005" "S006"

sprintf is equally useful for turning numbers back into readable text. Here we first find a student who is missing at least one quiz (using is.na and which, which we revisit below), and then build a one-line summary for them:

Code 
example.ix <- which(is.na(quiz1) | is.na(quiz2) | is.na(quiz3) | is.na(quiz4))[1]
example.name <- students[example.ix]

sprintf("%s's scores were: %s", example.name,
        paste(c(quiz1[example.ix],quiz2[example.ix],quiz3[example.ix],quiz4[example.ix]), collapse = ", "))
[1] "S001's scores were: 71, 64, NA, 59"

1.2.4 Special values: missing quizzes

is.na locates missing values anywhere in an object, including a whole matrix at once. With 100 students and a 10% missing rate per quiz, there are quite a few:

Code 
colSums(is.na(scores))
Quiz1 Quiz2 Quiz3 Quiz4 
   10    10    10    10
Code 
sum(is.na(scores))
[1] 40
Code 
head(which(is.na(scores), arr.ind = TRUE))
     row col
S008   8   1
S012  12   1
S015  15   1
S035  35   1
S039  39   1
S041  41   1

It is worth knowing what happens in the extreme case where a student has no recorded quiz at all: taking the mean of zero numbers is not zero, it is undefined, and R represents that with NaN (“not a number”) rather than NA:

Code 
mean(numeric(0))
[1] NaN
Code 
is.nan(mean(numeric(0)))
[1] TRUE

We will rely on this distinction later, so that our function can automatically flag a student with no data at all.

1.3 Writing the Core Function

1.3.1 A loop-based implementation

Before relying on which.min, it is worth seeing explicitly how a computer finds a minimum: by walking through the values one at a time and remembering the smallest one seen so far. This is the same control-flow pattern (a for loop with an if inside) used throughout numerical computing:

Code 
find.lowest <- function(x)
{
    n <- length(x)
    i.min <- 1
    x.min <- x[1]

    if(n > 1)
    {
        for(i in 2:n)
        {
            if(x[i] < x.min)
            {
                x.min <- x[i]
                i.min <- i
            }
        }
    }

    list(value = x.min, index = i.min)
}

find.lowest(valid)
$value
[1] 59

$index
[1] 3

1.3.2 A vectorized implementation

R’s built-in which.min (and, for dropping more than one value, order) does the same job in one call, and is what we will use going forward:

Code 
which.min(valid)
[1] 3
Code 
order(valid)
[1] 3 2 1

We now wrap the full calculation – discard missing quizzes, drop the lowest remaining score(s), average what’s left – into one function. Passing n.drop as an argument (rather than hard-coding “drop 1”) makes the function reusable for a different grading policy later. Following the special-value discussion above, a student with no valid quiz at all correctly returns NaN instead of causing an error:

Code 
compute.final.grade <- function(scores, n.drop = 1)
{
    valid <- scores[!is.na(scores)]

    if(length(valid) == 0)
    {
        return(list(raw = scores, kept = numeric(0), dropped = numeric(0), final = NaN))
    }

    #never drop every remaining score
    n.drop <- min(n.drop, length(valid) - 1)

    if(n.drop > 0)
    {
        drop.ix <- order(valid)[1:n.drop]
        dropped <- valid[drop.ix]
        kept <- valid[-drop.ix]
    }
    else
    {
        dropped <- numeric(0)
        kept <- valid
    }

    list(raw = scores, kept = kept, dropped = dropped, final = mean(kept))
}

1.4 Applying the Function to Every Student

apply(X, 1, FUN) calls FUN once per row of X – exactly what we need to run compute.final.grade on every student’s four quiz scores:

Code 
final.scores <- apply(roster[, quiz.cols], 1, function(x) compute.final.grade(x)$final)

summary(final.scores)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
  64.00   75.62   81.00   80.55   84.67  100.00
Code 
roster$final <- final.scores

The dropped score for each student is extracted the same way, and both new columns are added to roster:

Code 
roster$dropped <- sapply(1:nrow(roster), function(i) {
    r <- compute.final.grade(as.numeric(roster[i, quiz.cols]))
    if(length(r$dropped) == 0) NA else r$dropped
})

head(roster)

It is instructive to compare this with a fully vectorized alternative that needs no per-student function call at all: if we did not need to drop a quiz, the weighted total for every student could be computed in one line via matrix multiplication of the score matrix by a vector of weights:

Code 
w <- rep(1/4, 4)

weighted.total <- as.matrix(roster[, quiz.cols]) %*% w

head(weighted.total)
      [,1]
S001    NA
S002 76.25
S003 75.25
S004    NA
S005    NA
S006    NA
Code 
sum(is.na(weighted.total))
[1] 34

Notice that 34 students come back with NA – matrix multiplication has no way to skip a missing value on its own, so a single missed quiz spoils the whole sum. This is precisely why we wrote compute.final.grade: it encodes the extra logic (ignore missing quizzes, then drop the lowest) that a single matrix operation cannot express.

1.4.1 Saving and reloading the results

The final roster is worth keeping. A data frame can be written as a plain csv file for spreadsheets, or saved as an .RDS file to preserve it exactly (including the gender factor) for future R sessions:

Code 
write.csv(roster, file = "roster.csv", row.names = FALSE)

saveRDS(roster, file = "roster.RDS")

roster.reloaded <- readRDS("roster.RDS")

identical(roster, roster.reloaded)
[1] TRUE

1.5 Presenting the Results

1.5.1 Base R graphics

A quick histogram shows the distribution of final grades, with a vertical line marking the class average:

Code 
hist(roster$final, breaks = 15, col = "lightblue",
     main = "Distribution of Final Grades", xlab = "Final Grade")
abline(v = mean(roster$final), col = "red", lwd = 2)

A side-by-side boxplot compares the two gender groups:

Code 
boxplot(final ~ gender, data = roster,
        main = "Final Grade by Gender", xlab = "Gender", ylab = "Final Grade")

1.5.2 ggplot2

ggplot2 builds the same kind of comparison declaratively, by mapping columns of roster to visual properties and layering geometries with +. Here the boxplot is enhanced with the individual student scores jittered on top:

Code 
library(ggplot2)

ggplot(roster, aes(x = gender, y = final, fill = gender)) +
    geom_boxplot(show.legend = FALSE, alpha = 0.6) +
    geom_jitter(width = 0.15, size = 1.5, alpha = 0.6) +
    labs(
        title = "Final Grade by Gender",
        x = "Gender", y = "Final Grade"
    ) +
    theme_minimal()

We can also ask a natural follow-up question – does a strong first quiz predict a strong final grade? – with a scatter plot colored by gender:

Code 
ggplot(roster, aes(x = Quiz1, y = final, color = gender)) +
    geom_point(size = 2, alpha = 0.7) +
    labs(
        title = "Final Grade vs. Quiz 1 Score",
        x = "Quiz 1 Score", y = "Final Grade", color = "Gender"
    ) +

1.5.3 gt

Finally, gt turns a slice of roster into a polished report table instead of a plain printout. With 100 students we show just the first 10 rows: a title, grouped “Quizzes” columns, one decimal place on the computed grade, and a readable symbol for any missing quiz.
