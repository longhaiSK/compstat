1  Introduction to R Programming

2 The Mission

Throughout this unit we will use one running example to introduce the basic building blocks of R: vectors, strings, special values, matrices, data frames, lists, functions, file I/O, and graphics.

The mission: a class of students has taken four quizzes. Each student’s final grade is the average of their best three quiz scores – that is, we drop each student’s single lowest quiz score before averaging. To make things realistic, one student missed a quiz entirely, so we also need to handle a missing value correctly. We want to

  1. work out the calculation step by step for one student,
  2. package that calculation into a reusable function,
  3. apply the function to every student to get a full set of results, and
  4. present those results as a table and as plots.

This mirrors how real data-analysis code is usually built: explore on one case, generalize into a function, then apply and report.

3 Step by Step, for One Student

3.1 Vectors: recording quiz scores

The score on each quiz, across all students, is naturally stored as a vector. Here are the scores for four quizzes and eight students (in the same order):

Code 
quiz1 <- c(7,8,6,9,5,8,7,6)
quiz2 <- c(8,7,5,9,6,7,8,5)
quiz3 <- c(6,9,7,8,NA,9,6,7)
quiz4 <- c(9,8,8,7,7,8,5,8)

Notice the NA in quiz3: the fifth student missed that quiz. Ordinary arithmetic propagates a missing value rather than silently ignoring it, which is exactly the safe default we want:

Code 
quiz3
[1]  6  9  7  8 NA  9  6  7
Code 
mean(quiz3)
[1] NA
Code 
mean(quiz3, na.rm = TRUE)
[1] 7.428571

3.2 Strings: naming the quizzes and students

We could type out "Quiz1", "Quiz2", … by hand, but paste0 builds such labels programmatically – a habit that pays off the moment there are 40 quizzes instead of 4:

Code 
quiz.names <- paste0("Quiz", 1:4)

quiz.names
[1] "Quiz1" "Quiz2" "Quiz3" "Quiz4"

The students’ names are just another character vector:

Code 
students <- c("Ava","Ben","Cleo","Dae","Ellis","Faye","Gus","Hana")

students
[1] "Ava"   "Ben"   "Cleo"  "Dae"   "Ellis" "Faye"  "Gus"   "Hana"

sprintf is useful for turning numbers back into readable text, for example a one-line summary for a single student:

Code 
sprintf("%s's scores were: %s", students[5], paste(c(quiz1[5],quiz2[5],quiz3[5],quiz4[5]), collapse = ", "))
[1] "Ellis's scores were: 5, 6, NA, 7"

3.4 Special values: a missing quiz

is.na locates missing values anywhere in an object, including a whole matrix at once, and which(..., arr.ind = TRUE) reports their row/column position:

Code 
is.na(scores)
      Quiz1 Quiz2 Quiz3 Quiz4
Ava   FALSE FALSE FALSE FALSE
Ben   FALSE FALSE FALSE FALSE
Cleo  FALSE FALSE FALSE FALSE
Dae   FALSE FALSE FALSE FALSE
Ellis FALSE FALSE  TRUE FALSE
Faye  FALSE FALSE FALSE FALSE
Gus   FALSE FALSE FALSE FALSE
Hana  FALSE FALSE FALSE FALSE
Code 
which(is.na(scores), arr.ind = TRUE)
      row col
Ellis   5   3

It is worth knowing what happens in the extreme case where a student has no recorded quiz at all: taking the mean of zero numbers is not zero, it is undefined, and R represents that with NaN (“not a number”) rather than NA:

Code 
mean(numeric(0))
[1] NaN
Code 
is.nan(mean(numeric(0)))
[1] TRUE

We will rely on this distinction later, so that our function can automatically flag a student with no data at all.

3.5 Data frames: adding names and gender

A data frame lets us combine columns of different types – here, the students’ names and gender alongside their (numeric) quiz scores – into a single table:

Code 
gender <- factor(c("f","m","f","m","f","f","m","f"))

roster <- data.frame(name = students, gender = gender, scores)

roster

Because the row names of scores were dropped when it became columns of roster, we now identify students by the name column instead. grep can find, by pattern, which columns hold quiz scores – handy since we built those names programmatically earlier:

Code 
quiz.cols <- grep("^Quiz", names(roster))

quiz.cols
[1] 3 4 5 6
Code 
names(roster)[quiz.cols]
[1] "Quiz1" "Quiz2" "Quiz3" "Quiz4"

The usual data-frame subsetting tools – [ , ], $, and subset – work as expected, and tapply lets us summarize a column by group, e.g. the average Quiz1 score by gender:

Code 
roster[roster$gender == "f", ]
Code 
subset(roster, Quiz1 > 7)
Code 
tapply(roster$Quiz1, roster$gender, mean)

6.4 8.0

3.6 Lists: packaging one student’s full result

We now have everything needed to work out Ellis’s final grade by hand. A list is the natural container for the result, because it bundles pieces of different shapes – the raw scores, the scores kept, the score dropped, and a single final number – under one name:

Code 
ellis <- as.numeric(roster[roster$name == "Ellis", quiz.cols])

ellis
[1]  5  6 NA  7
Code 
valid <- ellis[!is.na(ellis)]

valid
[1] 5 6 7
Code 
i.min <- which.min(valid)

kept <- valid[-i.min]

final <- mean(kept)

result <- list(raw = ellis, kept = kept, dropped = valid[i.min], final = final)

result
$raw
[1]  5  6 NA  7

$kept
[1] 6 7

$dropped
[1] 5

$final
[1] 6.5

This confirms the calculation for one student. The rest of the unit turns this scratch work into something we can reuse and apply to everyone.

4 Writing the Core Function

4.1 A loop-based implementation

Before relying on which.min, it is worth seeing explicitly how a computer finds a minimum: by walking through the values one at a time and remembering the smallest one seen so far. This is the same control-flow pattern (a for loop with an if inside) used throughout numerical computing:

Code 
find.lowest <- function(x)
{
    n <- length(x)
    i.min <- 1
    x.min <- x[1]

    if(n > 1)
    {
        for(i in 2:n)
        {
            if(x[i] < x.min)
            {
                x.min <- x[i]
                i.min <- i
            }
        }
    }

    list(value = x.min, index = i.min)
}

find.lowest(valid)
$value
[1] 5

$index
[1] 1

4.2 A vectorized implementation

R’s built-in which.min (and, for dropping more than one value, order) does the same job in one call, and is what we will use going forward:

Code 
which.min(valid)
[1] 1
Code 
order(valid)
[1] 1 2 3

We now wrap the full calculation – discard missing quizzes, drop the lowest remaining score(s), average what’s left – into one function. Passing n.drop as an argument (rather than hard-coding “drop 1”) makes the function reusable for a different grading policy later. Following the special-value discussion above, a student with no valid quiz at all correctly returns NaN instead of causing an error:

Code 
compute.final.grade <- function(scores, n.drop = 1)
{
    valid <- scores[!is.na(scores)]

    if(length(valid) == 0)
    {
        return(list(raw = scores, kept = numeric(0), dropped = numeric(0), final = NaN))
    }

    #never drop every remaining score
    n.drop <- min(n.drop, length(valid) - 1)

    if(n.drop > 0)
    {
        drop.ix <- order(valid)[1:n.drop]
        dropped <- valid[drop.ix]
        kept <- valid[-drop.ix]
    }
    else
    {
        dropped <- numeric(0)
        kept <- valid
    }

    list(raw = scores, kept = kept, dropped = dropped, final = mean(kept))
}

Checking the function against the by-hand result for Ellis, and against the all-missing edge case:

Code

$kept
[1] 6 7

$dropped
[1] 5

$final
[1] 6.5

[1] NA NA NA NA

$kept
numeric(0)

numeric(0)

5 Applying the Function to Every Student

apply(X, 1, FUN) calls FUN once per row of X – exactly what we need to run compute.final.grade on every student’s four quiz scores:

Code 
final.scores <- apply(roster[, quiz.cols], 1, function(x) compute.final.grade(x)$final)

final.scores
     Ava      Ben     Cleo      Dae    Ellis     Faye      Gus     Hana 
8.000000 8.333333 7.000000 8.666667 6.500000 8.333333 7.000000 7.000000
Code 
roster$final <- final.scores

The dropped score for each student is extracted the same way, and both new columns are added to roster:

Code 
roster$dropped <- sapply(1:nrow(roster), function(i) {
    r <- compute.final.grade(as.numeric(roster[i, quiz.cols]))
    if(length(r$dropped) == 0) NA else r$dropped
})

roster

It is instructive to compare this with a fully vectorized alternative that needs no per-student function call at all: if we did not need to drop a quiz, the weighted total for every student could be computed in one line via matrix multiplication of the score matrix by a vector of weights:

Code 
w <- rep(1/4, 4)

as.matrix(roster[, quiz.cols]) %*% w
      [,1]
Ava   7.50
Ben   8.00
Cleo  6.50
Dae   8.25
Ellis   NA
Faye  8.00
Gus   6.50
Hana  6.50

Notice that Ellis’s entry comes back as NA – matrix multiplication has no way to skip a missing value on its own. This is precisely why we wrote compute.final.grade: it encodes the extra logic (ignore missing quizzes, then drop the lowest) that a single matrix operation cannot express.

5.1 Saving and reloading the results

The final roster is worth keeping. A data frame can be written as a plain csv file for spreadsheets, or saved as an .RDS file to preserve it exactly (including the gender factor) for future R sessions:

Code 
write.csv(roster, file = "roster.csv", row.names = FALSE)

saveRDS(roster, file = "roster.RDS")

roster.reloaded <- readRDS("roster.RDS")

identical(roster, roster.reloaded)
[1] TRUE

6 Presenting the Results

6.1 Base R graphics

A quick histogram shows the distribution of final grades, with a vertical line marking the class average:

Code 
hist(roster$final, breaks = 5, col = "lightblue",
     main = "Distribution of Final Grades", xlab = "Final Grade")
abline(v = mean(roster$final), col = "red", lwd = 2)

A side-by-side boxplot compares the two gender groups:

Code 
boxplot(final ~ gender, data = roster,
        main = "Final Grade by Gender", xlab = "Gender", ylab = "Final Grade")

6.2 ggplot2

ggplot2 builds the same kind of comparison declaratively, by mapping columns of roster to visual properties and layering geometries with +. Here the boxplot is enhanced with the individual student scores jittered on top:

Code 
library(ggplot2)

ggplot(roster, aes(x = gender, y = final, fill = gender)) +
    geom_boxplot(show.legend = FALSE, alpha = 0.6) +
    geom_jitter(width = 0.1, size = 2) +
    labs(
        title = "Final Grade by Gender",
        x = "Gender", y = "Final Grade"
    ) +
    theme_minimal()

We can also ask a natural follow-up question – does a strong first quiz predict a strong final grade? – with a scatter plot colored by gender:

Code 
ggplot(roster, aes(x = Quiz1, y = final, color = gender)) +
    geom_point(size = 2) +
    labs(
        title = "Final Grade vs. Quiz 1 Score",
        x = "Quiz 1 Score", y = "Final Grade", color = "Gender"
    ) +
    theme_minimal()
